## Hard rules for every executor (repo-wide)

- Package manager is **pnpm** (never npm). Gates from repo root: `pnpm lint`, `pnpm typecheck`,
  `pnpm test`. Web-only: `pnpm --filter @maqrivo/web test` (vitest, tests in `apps/web/test/`).
- **Every new i18n key goes into BOTH `apps/web/messages/en.json` AND `apps/web/messages/fr.json`.**
  A missing key has crashed SSR before (MISSING_MESSAGE) — this is the repo's most fragile seam.
- Server actions: session check via `getSessionContext()`, zod-validate inputs, return
  `{ ok: boolean; error?: string }`, call `revalidatePath` on mutated paths. Exemplar:
  `apps/web/src/server/recipes/actions.ts` (`adjustPantryQuantityAction`, lines 214-232).
- Icons: `@phosphor-icons/react/dist/ssr/*` in server components, `dist/csr/*` in client ones.
- Paths contain `[locale]` and `(app)` — always quote them in shell commands; the read/grep/glob
  tools handle them unquoted.
- DB schema changes: edit `packages/db/src/schema/*.ts`, then `pnpm db:generate` and
  `pnpm db:migrate` (drizzle-kit). Container bootstrapping runs migrations on deploy.

## Findings considered and rejected

- **Adding a `sourceUrl` viewer link to the catalogue table**: `RemoteCatalogue` (flipbook.ts)
  carries no viewer URL — only per-page image URLs. Not worth a migration for a link we
  cannot populate reliably. Revisit if an adapter gains viewer URLs.
- **Unique DB index on promotions for dedup**: promotion rows legitimately repeat across
  catalogue windows; a partial unique index over nullable columns adds migration risk for
  what a pre-check query (plan 003) solves. Revisit if duplicates persist.
- **Auto-running extraction with no budget cap**: rejected without a kill-switch env var —
  unattended paid AI calls are the one automation the repo's "no evidence, no deal" principle
  forbids blindly. Plan 005 ships the budget guard as part of the job.
- **Rewriting the planner for multi-unit support (kg/ml/l/unit candidates)**: real finding
  (planner.ts:396 only branches on `packageUnit === "g"`) but touches the solver contract —
  deferred as its own future plan after 011 lands data normalization.
